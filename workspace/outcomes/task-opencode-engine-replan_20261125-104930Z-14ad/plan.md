## Plan

### What / where / why
Insert an `ExecutionEngine` seam at the six controller calls to `ToolExecutionHub.process_request`; lifecycle (claim, heartbeat, deadline, close, persistence) stays in controllers. Engine identity is persisted per execution, run and await state. A headless `OpenCodeExecutionEngine` routes every tool call through an orchestrator-hosted, per-run, ownership-fenced bridge, and every model call through an in-process fixed-route relay, so all sidecar work fate-shares with the claiming process. Covers In-1..In-6; Out-1..Out-4 untouched. Baseline: earlier run's plan v4, re-verified against current code.

### Segment today (Q1)
- Six call sites: `orchestrator_controller.py` execute (770) and resume (992); `ag_ui_controller.py` `_run_resume_segment` (1391) and `_run_fresh_segment` (1768); `agent_controller.py` `executeRequest` (175) and `resumeRun` (274). `tool_hub.py` 1564 is the nested `task_local` call and stays internal.
- Orchestrator and AG-UI segments are one hub task inside `session_close_service.manage_run` (153), via `_managed_hub_process` (461) or `_stream_run` (807). `manage_run` owns heartbeat, deadline watchdog (`segment_deadline_sec`, 186), cancel event + `task.cancel()`, and awaits the worker before release; the claim is `run_lifecycle.try_create_active_run` (334).
- Legacy paths have no `ExecutionRun` claim and no `manage_run`; `executeRequest` creates a RUNNING `Execution` (`_create_execution_record`, 100) and persists only that row (210–216). Unchanged under internal.
- Persisted fields: `executions` (`status, result, error_message, config, origin`); `execution_runs` (`execution_id, thread_key, run_id, origin, channel, status, heartbeat_at, started_at, finished_at`); await snapshot `llm_states` (`execution_id, thread_id, thread_key, run_id, tool_call_id, status, state_payload`) via `create_state` (`execution_state_service.py` 106) from orchestrator 328, AG-UI 599, agent 132.
- Result is the hub dict (`success, response, error, error_code`, counters, tokens, `tool_calls_info, agui_tool_calls, text_streamed, awaits_response, pending_tools, pending_tool, interrupts, state`); `state` from `_build_await_result` (857). Resume uses `resume_tool_results`, `resolve_resume_model`, `resolve_resume_max_tool_calls`; `prepare_hook_permission_resume_events` stays internal-only.
- The hub binds the MCP user token and request catalog as ContextVars for its own task (`tool_hub.py` 237–241, reset 853–855); `fetch_mcp_tools` binds and resets the token around listing (`mcp_agent_service.py` 395–414). The internal model path calls only `POST {LITELLM_BASE_URL}/v1/chat/completions` (`mcp_agent_service.py` 669).

### Design decisions
- D1 (In-1) `engines/contract.py`: v1 `SegmentRequest` (all current `process_request` kwargs incl. `cancel_check`, + `event_sink`, + optional `resolved_tools`), `EngineEvent` (text/tool/usage), `SegmentResult` (TypedDict of hub keys), `AwaitEnvelope{engine, contractVersion, payload}`, `ENGINE_CONTRACT_VERSION = 1`.
- D2 (In-1) `engines/base.py` protocol: `name`, `contract_version`, `capabilities()`, `async run_segment`. Failures return `success: False`; `CancelledError` re-raised only after engine-owned work stopped (D14).
- D3 (In-2) `engines/internal.py` forwards kwargs unchanged with `event_sink=None`; rejects non-`None` `resolved_tools`. `task_local` stays inside the hub.
- D4 (In-2, C-5) `engines/resolver.py`: `resolve_fresh_engine()` reads `ORCHESTRATOR_ENGINE` and is called only where a durable object is created: orchestrator `initiate` (575), AG-UI `_create_agui_execution` (567), legacy `_create_execution_record` (102). `resolve_persisted_engine(name, version)` serves every segment of an existing object: orchestrator execute and resume from `Execution.engine`, AG-UI and legacy resume from `llm_states`. It never chooses by env; it returns the engine only if runnable here: `internal`/1 always, `opencode`/1 only while `ORCHESTRATOR_ENGINE=opencode` (bridge, relay and validated config exist only then, D12/D18/D27; none before Slice 6); else `EngineMismatch` (D7).
  - AG-UI `ThreadSession` holds lifecycle only (`execution_models.py` 55–85) and each AG-UI or legacy fresh run creates its own `Execution`, so those runs pin at that row; consecutive AG-UI runs on one thread may differ by engine because the client resends messages and no engine state lives on the thread.
- D5 (Q2, C-5) Columns `engine VARCHAR(32) NOT NULL DEFAULT 'internal'`, `engine_contract_version INTEGER NOT NULL DEFAULT 1` on `executions`, `execution_runs`, `llm_states`; `state_payload` unchanged (C-6). `create_execution` (43), `try_create_active_run` (334), `create_state` (106) gain keyword params defaulting to internal/1; `update_execution` (64) gains none, so `executions.engine` is written once at creation and never changed.
  - Stamping: the three creation points pass the fresh engine; every `try_create_active_run` (orchestrator 718, 939; AG-UI 1286, 1632) and `create_state` (orchestrator 328, AG-UI 599, agent 132) passes the engine resolved for that object, so each `ExecutionRun` and await row equals its `Execution`.
- D6 (Q2) Alembic `20261124_engine_identity`, down-revision `20250816_phase3_lifecycle` (head). Server defaults backfill all three tables as internal/1 with the phase-3 adopt-if-present pattern; downgrade drops the columns; `executions.config` not rewritten.
- D7 (Q2, C-5) Mismatch check after load, before any claim: orchestrator execute after `get_execution` (699) before `try_create_active_run` (718); orchestrator resume after `get_state` (890) before `try_claim_state_for_resume` (935), also requiring state engine/version = `Execution`'s; AG-UI `_handle_tool_response` after `get_resume_hold_by_tool_call_id` (1180) before claim (1257); legacy `resumeRun` after state load (251) before the hub call.
  - REST: 409 `{"success":false,"errorCode":"ENGINE_MISMATCH","error":"State was created by engine '<e>' contract v<n>; this deployment cannot run it"}` (shape of `_run_conflict_payload`). AG-UI: `RunErrorEvent("ENGINE_MISMATCH: …")`. `Execution` status and state (`AWAITING_RESPONSE`) untouched, no `ExecutionRun`; legacy returns before its `DISCARDED` branch (286). Not a failed segment: runnable again once the engine is available, or closed by the caller (C-3).
  - Internal sessions and state run on internal under either setting, with every global flag as configured; no OpenCode gate touches them.
- D8 (Q3) OpenCode v1 has no resume mode: never awaits, writes no `llm_states`, `durable_resume=false`. First mode later (Out-3) is the translated snapshot: a session reference pins resume to one process's sidecar (D11), breaking replica independence (§10). Rejection tested with a crafted `engine='opencode'` row.
- D9 (Q4, In-4) `engines/capabilities.py`: `headless_segment, workspace_file_ops, mcp_tools, streaming_output, agui_frontend_interrupts, durable_resume, hooks, permission_asks, subagents, context_compaction, multimodal_reads, local_subprocess, workspace_free`. Internal: all true. OpenCode: `headless_segment`, `workspace_file_ops`, `streaming_output` true; `mcp_tools=subset` (D22); rest false.
- D10 (Q4, In-4) `require_capabilities(engine, needs)` → 400 / `RunErrorEvent` `ENGINE_CAPABILITY_UNSUPPORTED` naming the capability; denial logged with engine, version, capability. Internal never gated. Gate points:

  - AG-UI fresh: frontend-tool gate before binding resolution (1569); binding-dependent gates after `except BindingError` (1597), before `sanitize_execution_config` (1601) and `_create_agui_execution` (1621). Earlier `ensure_thread_session` (1449), `_prepare_thread_claims` (1474), `ensure_runtime` (1582) run first as for binding errors; no rows; thread runnable.
  - Structural gates, never waivable: non-empty `frontendTools`; `hooks` (below); `workspace_free` when AG-UI `input_binding is None` and always on legacy; then D22 tool resolution, last.
  - `hooks` gate, only when `Config.HOOKS_ENABLED` (default false, `config.py` 289): `engines/opencode/hook_preflight.py` `preflight_hook_path(...) -> Optional[str]` returns a path only if the run will use an already-existing dir in place: orchestrator `execution.workspace_path` that `is_dir()` (the no-provision branch of `ensure_input_workspace`, `binding_runtime.py` 238–241); AG-UI in-place `workspacePath` that `is_dir()`; AG-UI `input` with `should_provision_in_place` true, a local source, whose `select_relative_workspace` path `is_dir()`. Path → `load_hooks_for_workspace(path)` (`loader.py` 256); any event → reject. `None` (copy, git, shared folder, missing or to-be-recovered workspace; `load_hooks_for_workspace` would see no file) → reject `hooks`, "hook configuration cannot be verified before provisioning". No provisioning, no rows.

  - A waived capability runs reduced (tool not offered; OpenCode-native compaction, A8; multimodal reads return D12's tool error), logged `opencode_capability_waived` with engine, version, names; response shape unchanged. Shipped defaults with no waiver reject every OpenCode run that lists local tools. Waivers never apply to frontend tools, hooks, `workspace_free` or D22.
  - In-segment failures are attempts (§12): `local_context is None` (ignored `workspacePath`, 387); hook config appearing between gate and segment start or mid-run (D12).
- D11 (C-2) One loopback sidecar per orchestrator process, operator-launched, same network namespace; no workspace mount; each session rooted in an empty per-run scratch dir and tagged `(process_instance_id, run_pk)`; orchestrator-composed system prompt per session (A4); session MCP config and provider config both point at this process (D12, D27). If A13 holds, the client also sends the sidecar's API credential (depth only).
- D12 (C-2) `engines/opencode/bridge.py`: internal MCP route mounted in `main.py` (99–102) only when engine=opencode.
  - Listing `list_litellm_tools(exclude_base={"task","ask_user","execute","git_status","git_diff","git_log","git_add","git_commit","git_checkout_branch"}, …)` (1042) + `resolved_tools.mapped`, no AG-UI tools; only when `local_tool_provider.enabled`. Dispatch refuses any name outside the list: "not available", nothing executes.
  - MCP dispatch per call in the handler task: `entry = scope.resolved.mapped[opencode_name]` (else "not available"); `t1 = bind_mcp_user_token(scope.user_token)`, `t2 = bind_request_mcp_tools(scope.resolved.mcp_tools)` (keyed by attributed `MCPTool.name`, 75); `await mcp_service.execute_mcp_tool(entry.mcp_tool.name, args)` (never `original_name`, which `find_tool_by_name` 486 cannot resolve for suffixed tools); `finally` reset `t2`, then `t1`.   - Local calls via `LocalToolProvider.execute` (1083) with `bind_hooks_suppressed()` (D26): tool policy, `resolve_within`, path policy, workspace opener.

  - When `HOOKS_ENABLED`, the engine reloads hook config on the materialized `local_context.workspace_path` before session create (D25 order) and each local call re-reads it; any event (a non-bridge writer) → denied, segment fails `ENGINE_CAPABILITY_UNSUPPORTED` (hooks) via D14. - D13 (C-4) `maxToolCalls`: request → segment config → `MAX_TOOL_CALLS`, counted in the bridge. `OPENCODE_REQUEST_TIMEOUT_SEC` is a per-request infrastructure guard; the segment deadline (D24) caps the run. `OPENCODE_MODEL`/`OPENCODE_PROVIDER` inert unless engine=opencode.
- D14 (C-1) Shielded stop sequence on cancel, `CancelledError`, completion, failure or lost ownership; swallows repeated `task.cancel()`; returns or re-raises only after step 6:
  1. Close bridge and relay admission for the run; late calls get "run stopping".  2. Send abort to the run's session (best effort).  3. Cancel and await every open relay stream; await every in-flight bridge call (MCP cancelled then awaited; file tools run to completion).  4. Revoke the token.
  5. Confirm: poll status and list-by-tag `(process_instance_id, run_pk)` (A1, A6), each request bounded by `OPENCODE_REQUEST_TIMEOUT_SEC`; confirmed only when a sidecar answering the pinned version reports the run's session idle or absent (absent covers a sidecar restart, A7). After one unconfirmed timeout send delete; then re-send abort/delete and poll with capped backoff (1 s doubling to 30 s), no attempt cap, no elapsed-time exit; each interval logs `opencode_stop_unconfirmed`. Unreachable sidecar = unconfirmed.  6. Delete the idle session (best effort, idempotent), then drop the run scope from the registry.
  - Step 5 is skipped only when no session create was ever sent (failure in `check_version`, sweep or hook reload); a timed-out create is confirmed by tag.
  - "Stopped" = steps 3–5 all hold: no bridge call, no relay stream, and the sidecar confirms the session idle or gone. The worker lives until then, so `manage_run` keeps heartbeat fresh, `worker_cancellation_slow` fires and the claim is finalized only after confirmation; a sidecar that never answers holds the claim until it returns or the orchestrator process exits (then D15).
- D15 (C-1) Crash orphans: the bridge (D12) and relay (D27) live in the claiming process, so its death refuses the orphan's tool and model calls (connection refused); after restart its bearer is unknown (401). Only a model request already in flight at the crash completes upstream, as with an internal crash. Stale reclaim (`mark_stale_runs_failed`, 531) is unchanged and happens only after `RUN_HEARTBEAT_STALE_SEC`.
  - `sweep.py` aborts and deletes tagged sessions absent from the live scope registry (a stopping run stays registered until D14 step 6), then confirms each idle or absent by D14 step 5's rule; best effort at startup, mandatory at each segment start after `check_version`, bounded by `min(OPENCODE_REQUEST_TIMEOUT_SEC, deadline.remaining())`. Unconfirmed → segment fails `UNAVAILABLE` before session create, logged `opencode_orphan_sweep_unconfirmed`, state per §12, so no new run shares a sidecar with an unconfirmed orphan. A run reclaimed onto another replica uses that replica's sidecar; the orphan is confirmed by the next segment on its own sidecar.
- D16 (Q5, C-3) Every in-segment failure runs D14 then returns `success: False`; controllers apply the §12 table unchanged; raw sidecar or provider bodies never returned. Codes: `UNAVAILABLE` (down, health fail, version mismatch); `TIMEOUT` (request timeout, deadline); `ENGINE_PROTOCOL_ERROR` (malformed event, partial stream, relay request denied by D27); provider errors from the relay's upstream status via `_llm_upstream_error` (`mcp_agent_service.py` 32, unchanged); `RUN_LIFECYCLE_FAILED` on lost ownership (D20); `ENGINE_CAPABILITY_UNSUPPORTED` (mid-run hooks). `ENGINE_TOOL_UNSUPPORTED` only pre-claim (D22).

  - `_require_loopback_url(name, value)` for `OPENCODE_BASE_URL` and `OPENCODE_TOOL_BRIDGE_URL`: scheme `http`, no userinfo/query/fragment, hostname `localhost` or `ipaddress.ip_address(host).is_loopback`; else `ValueError` naming the variable. Positive timeout, valid provider, waiver names in the allowed set; a provider mode with no Slice 3 relay route set (D27) → `ValueError`; native requires `OPENCODE_MODEL`, both native vars, and its recorded auth header.
- D19 OpenCode does not depend on `ModelClient` (Out-1); discovery stays orchestrator-side (Out-2).

### Risks
- Large AG-UI closures: Slice 2 swaps only the call expression; Slice 1 guards behaviour; moved gates touch only OpenCode branches.
- OpenCode runs lose shell and git until an isolated runner exists (Phase 5); explicit by gate, reduced only by operator waiver. Disabling a global flag instead also affects internal runs; docs recommend the waiver. Loopback-only forbids a remote sidecar; containers co-locate it (Phase 6).
- A3 or A14 stopping means nothing beyond Slice 4 ships; `internal` unaffected. The relay adds one loopback hop per model call and holds provider keys in the orchestrator for native mode.
- The body-key allowlist couples to the pinned version: an OpenCode upgrade that adds a key fails closed (`ENGINE_PROTOCOL_ERROR`) until fixtures and `RELAY_ROUTES` are re-recorded in the same PR as the version bump.
- D20 adds one DB read per tool and model call; per-call hook re-read only when `HOOKS_ENABLED`. Bridge and relay share the app port: gateways must not expose `/internal/*`.
- A hung or down sidecar holds every stopping run's claim (thread busy, 409 on new segments) until it answers or is restarted; deliberate per C-1, visible via `worker_cancellation_slow`/`opencode_stop_unconfirmed`; documented in `docs/ORCHESTRATOR.md` §12 with the restart remedy.
- Rollback to `internal` leaves existing opencode orchestrator sessions answering 409 `ENGINE_MISMATCH` (not closed) until the env is restored or the caller closes and re-initiates; documented in `readme.md` and §12.
- Input-branch `ensure_runtime` (1582) creates the runtime dir before a rejection; idempotent, no lifecycle row.
- With `HOOKS_ENABLED`, OpenCode serves only existing in-place workspaces (copied, git, shared-folder and recovered ones rejected) until Phase 5; deliberate, since provisioning before the row would change the internal lifecycle (C-6).
