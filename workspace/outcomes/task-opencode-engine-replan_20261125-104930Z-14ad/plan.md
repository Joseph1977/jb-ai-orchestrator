## Plan

### What / where / why
Insert an `ExecutionEngine` seam at the six controller calls to `ToolExecutionHub.process_request`; lifecycle (claim, heartbeat, deadline, close, persistence) stays in controllers. Engine identity is persisted per execution, run and await state. A headless `OpenCodeExecutionEngine` routes every tool call through an orchestrator-hosted, per-run, ownership-fenced bridge, and every model call through an in-process relay, so all sidecar work fate-shares with the claiming process. Covers In-1..In-6; Out-1..Out-4 untouched. Baseline: earlier run's plan v4, re-verified against current code.

### Segment today (Q1)
- Six call sites: `orchestrator_controller.py` execute (770) and resume (992); `ag_ui_controller.py` `_run_resume_segment` (1391) and `_run_fresh_segment` (1768); `agent_controller.py` `executeRequest` (175) and `resumeRun` (274). `tool_hub.py` 1564 is the nested `task_local` call and stays internal.
- Orchestrator and AG-UI segments are one hub task inside `session_close_service.manage_run` (153), via `_managed_hub_process` (461) or `_stream_run` (807). `manage_run` owns heartbeat, deadline watchdog (`segment_deadline_sec`, 186), cancel event + `task.cancel()`, and awaits the worker before release; the claim is `run_lifecycle.try_create_active_run` (334).
- Legacy paths have no `ExecutionRun` claim and no `manage_run`; `executeRequest` creates a RUNNING `Execution` (`_create_execution_record`, 100) and persists only that row (210–216). Unchanged under internal.
- Persisted fields: `executions` (`status, result, error_message, config, origin`); `execution_runs` (`execution_id, thread_key, run_id, origin, channel, status, heartbeat_at, started_at, finished_at`); await snapshot `llm_states` (`execution_id, thread_id, thread_key, run_id, tool_call_id, status, state_payload`) via `create_state` (`execution_state_service.py` 106) from orchestrator 328, AG-UI 599, agent 132.
- Result is the hub dict (`success, response, error, error_code`, counters, tokens, `tool_calls_info, agui_tool_calls, text_streamed, awaits_response, pending_tools, pending_tool, interrupts, state`); `state` from `_build_await_result` (857). Resume uses `resume_tool_results`, `resolve_resume_model`, `resolve_resume_max_tool_calls`; `prepare_hook_permission_resume_events` stays internal-only.
- The hub binds the MCP user token and request catalog as ContextVars for its own task (`tool_hub.py` 237–241, reset 853–855); `fetch_mcp_tools` binds and resets the token around listing (`mcp_agent_service.py` 395–414).

### Design decisions
- D1 (In-1) `engines/contract.py`: v1 `SegmentRequest` (all current `process_request` kwargs incl. `cancel_check`, + `event_sink`, + optional `resolved_tools`), `EngineEvent` (text/tool/usage), `SegmentResult` (TypedDict of hub keys), `AwaitEnvelope{engine, contractVersion, payload}`, `ENGINE_CONTRACT_VERSION = 1`.
- D2 (In-1) `engines/base.py` protocol: `name`, `contract_version`, `capabilities()`, `async run_segment`. Failures return `success: False`; `CancelledError` re-raised only after engine-owned work stopped (D14).
- D3 (In-2) `engines/internal.py` forwards kwargs unchanged with `event_sink=None`; rejects non-`None` `resolved_tools`. `task_local` stays inside the hub.
- D4 (In-2) `engines/resolver.py`: `resolve_fresh_engine()` reads `ORCHESTRATOR_ENGINE`; `resolve_persisted_engine(name, version)` never reads the environment. Used at all six call sites.
- D5 (Q2, C-5) Columns `engine VARCHAR(32) NOT NULL DEFAULT 'internal'`, `engine_contract_version INTEGER NOT NULL DEFAULT 1` on `executions`, `execution_runs`, `llm_states`; `state_payload` unchanged (C-6). `create_execution` (43), `try_create_active_run`, `create_state` gain keyword params defaulting to internal/1; `update_execution` (64) gains optional engine params.
  - Stamping: legacy `_create_execution_record` and AG-UI `_create_agui_execution` (569) pass the fresh engine; orchestrator initiate (575) stamps it and each execute/resume segment updates it in the claim transaction. Audit only; D7 never reads `executions.engine`.
- D6 (Q2) Alembic `20261124_engine_identity`, down-revision `20250816_phase3_lifecycle` (head). Server defaults backfill all three tables as internal/1 with the phase-3 adopt-if-present pattern; downgrade drops the columns; `executions.config` not rewritten.
- D7 (Q2, C-5) Mismatch check after state load, before any claim: orchestrator resume after `get_state` (890) before `try_claim_state_for_resume` (935); AG-UI `_handle_tool_response` after `get_resume_hold_by_tool_call_id` (1180) before claim (1257); legacy `resumeRun` after state load (251) before the hub call.
  - REST: 409 `{"success":false,"errorCode":"ENGINE_MISMATCH","error":"Run state was created by engine '<e>' contract v<n>; this deployment cannot resume it"}` (shape of `_run_conflict_payload`). AG-UI: `RunErrorEvent("ENGINE_MISMATCH: …")`. State stays `AWAITING_RESPONSE`, no `ExecutionRun`; legacy returns before its `DISCARDED` branch (286).
  - Internal state resumes on internal under either setting, with every global flag as configured; no OpenCode gate touches internal resumes.
- D8 (Q3) OpenCode v1 has no resume mode: never awaits, writes no `llm_states`, `durable_resume=false`. First mode later (Out-3) is the translated snapshot: a session reference pins resume to one process's sidecar (D11), breaking replica independence (§10). Rejection tested with a crafted `engine='opencode'` row.
- D9 (Q4, In-4) `engines/capabilities.py`: `headless_segment, workspace_file_ops, mcp_tools, streaming_output, agui_frontend_interrupts, durable_resume, hooks, permission_asks, subagents, context_compaction, multimodal_reads, local_subprocess, workspace_free`. Internal: all true. OpenCode: `headless_segment`, `workspace_file_ops`, `streaming_output` true; `mcp_tools=subset` (D22); rest false.
- D10 (Q4, In-4) `require_capabilities(engine, needs)` → 400 / `RunErrorEvent` `ENGINE_CAPABILITY_UNSUPPORTED` naming the capability; denial logged with engine, version, capability. Internal never gated. Gate points:
  - Orchestrator `execute`: after `_segment_config` (707), before the claim session (710); `Execution` status untouched. Legacy `executeRequest`: before `_create_execution_record()` (158).
  - AG-UI fresh: frontend-tool gate before binding resolution (1569); binding-dependent gates after `except BindingError` (1597), before `sanitize_execution_config` (1601) and `_create_agui_execution` (1621). Earlier `ensure_thread_session` (1449), `_prepare_thread_claims` (1474), `ensure_runtime` (1582) run first as for binding errors; no rows; thread runnable.
  - Engine-local gates only, no process flag required: non-empty `frontendTools`; `hooks` when `Config.HOOKS_ENABLED` and `load_hooks_for_workspace(path)` (`hooks/loader.py` 256) yields any event; `workspace_free` when AG-UI `input_binding is None` and always on legacy; then D22 tool resolution, last.
  - Not gated, reported false and documented: `subagents` (`task_local` never offered), `context_compaction` (history is OpenCode's own; bridge keeps `offload_tool_result_if_needed`, `context_compaction.py` 174), `local_subprocess` (D26), `multimodal_reads` (explicit tool error, D12). `ask_user_local` never offered, so no await arises.
  - In-segment failures are attempts (§12): `local_context is None` (ignored `workspacePath`, 387); hook config appearing mid-run (D12).
- D11 (C-2) One loopback sidecar per orchestrator process, operator-launched, same network namespace; no workspace mount; each session rooted in an empty per-run scratch dir and tagged `(process_instance_id, run_pk)`; orchestrator-composed system prompt per session (A4); session MCP config and provider config both point at this process (D12, D27). If A13 holds, the client also sends the sidecar's API credential (depth only).
- D12 (C-2) `engines/opencode/bridge.py`: internal MCP route mounted in `main.py` (99–102) only when engine=opencode.
  - Listing `list_litellm_tools(exclude_base={"task","ask_user","execute","git_status","git_diff","git_log","git_add","git_commit","git_checkout_branch"}, …)` (1042) + `resolved_tools.mapped`, no AG-UI tools; only when `local_tool_provider.enabled`. Dispatch refuses any name outside the list: "not available", nothing executes.
  - MCP dispatch per call in the handler task: name ∈ `scope.resolved.mapped`; `t1 = bind_mcp_user_token(scope.user_token)`, `t2 = bind_request_mcp_tools(scope.resolved.mcp_tools)`; `await mcp_service.execute_mcp_tool(original_name, args)`; `finally` reset `t2`, then `t1`. Never relies on inherited ContextVars.
  - Local calls via `LocalToolProvider.execute` (1083) with `bind_hooks_suppressed()` (D26): tool policy, `resolve_within`, path policy, workspace opener.
  - Hook-config write guard (P016), before dispatch: `write_file`, `edit_file`, `create_file`, `create_folder` whose `resolve_within`-normalized `path`, compared casefolded by component, equals or lies under `.cursor/hooks.json`, `.claude/hooks.json` or `.claude/settings.json` (the `_load_hooks` set, `loader.py` 207–228) → "hook configuration is read-only under engine opencode"; `write_output_local`/`edit_output_local` on `shared_folder` output whose absolute target equals or lies under those three absolute workspace paths → same. Pure check, no I/O.
  - When `HOOKS_ENABLED`, each local call also re-reads hook config; any event (a non-bridge writer) → denied, segment fails `ENGINE_CAPABILITY_UNSUPPORTED` (hooks) via D14. Residual: a non-bridge write landing during an in-flight call is the same load-then-execute window internal `run_hooks` already has.
  - Media markers (`multimodal: true`, `local_tool_provider.py` 192) → tool error "multimodal reads not supported by engine opencode", no path. Results pass `offload_tool_result_if_needed` as on internal.
  - Per-run 256-bit in-memory bearer bound to `(run_pk, LocalToolContext, registry, budget, user MCP token, ResolvedTools)`; bad token → 401. User MCP token never reaches the sidecar; OpenCode built-ins disabled per session (A2).
- D13 (C-4) `maxToolCalls`: request → segment config → `MAX_TOOL_CALLS`, counted in the bridge. `OPENCODE_REQUEST_TIMEOUT_SEC` is a per-request infrastructure guard; the segment deadline (D24) caps the run. `OPENCODE_MODEL`/`OPENCODE_PROVIDER` inert unless engine=opencode.
- D14 (C-1) Shielded stop sequence on cancel, `CancelledError`, completion, failure or lost ownership; swallows repeated `task.cancel()`:
  1. Close bridge and relay admission for the run; late calls get "run stopping".  2. Send abort (best effort).  3. Cancel and await every open relay stream; await every in-flight bridge call (MCP cancelled then awaited; file tools run to completion).  4. Revoke the token.  5. Poll idle (A6), bounded by `OPENCODE_REQUEST_TIMEOUT_SEC`; failure logs `opencode_idle_unconfirmed`, then return or re-raise.
  - "Stopped" means no bridge call and no relay stream live for the run, verified in-process after step 4: the sidecar has no tool or model path left, whatever its state. The worker lives until then, so heartbeat stays fresh and `worker_cancellation_slow` fires; nothing released on elapsed time.
- D15 (C-1, P015) Crash orphans: the bridge (D12) and relay (D27) live in the claiming process, so its death refuses the orphan's tool and model calls (connection refused); after restart its bearer is unknown (401). Only a model request already in flight at the crash completes upstream, as with an internal crash. Stale reclaim (`mark_stale_runs_failed`, 531) is unchanged and happens only after `RUN_HEARTBEAT_STALE_SEC`.
  - `sweep.py` aborts and deletes tagged sessions absent from the live scope registry, at startup and each segment start after `check_version`, bounded by `min(OPENCODE_REQUEST_TIMEOUT_SEC, deadline.remaining())`. Hygiene only (leftover session records): failure logs `opencode_orphan_sweep_pending` and the segment continues, since orphans hold no capability.
- D16 (Q5, C-3) Every in-segment failure runs D14 then returns `success: False`; controllers apply the §12 table unchanged; raw sidecar or provider bodies never returned. Codes: `UNAVAILABLE` (down, health fail, version mismatch); `TIMEOUT` (request timeout, deadline); `ENGINE_PROTOCOL_ERROR` (malformed event, partial stream); provider errors from the relay's upstream status via `_llm_upstream_error` (`mcp_agent_service.py` 32, unchanged); `RUN_LIFECYCLE_FAILED` on lost ownership (D20); `ENGINE_CAPABILITY_UNSUPPORTED` (mid-run hooks). `ENGINE_TOOL_UNSUPPORTED` only pre-claim (D22).
- D17 (In-3) Sidecar stream supplies text, usage, completion; the bridge supplies authoritative `TOOL_CALL_*` events, `tool_calls_info` and counters. `event_sink` publishes via `agui_event_service` and sets `text_streamed`.
- D18 (In-5) `config.py`: `ORCHESTRATOR_ENGINE` (default `internal`), `OPENCODE_BASE_URL`, `OPENCODE_REQUEST_TIMEOUT_SEC=300`, `OPENCODE_MODEL`, `OPENCODE_PROVIDER=litellm|native`; infra `OPENCODE_TOOL_BRIDGE_URL` (default `http://127.0.0.1:8000`, serves bridge and relay), `OPENCODE_NATIVE_BASE_URL`, `OPENCODE_NATIVE_API_KEY` (native only). `validate_config` (384) checks the engine value; only when opencode:
  - `_require_loopback_url(name, value)` for `OPENCODE_BASE_URL` and `OPENCODE_TOOL_BRIDGE_URL`: scheme `http`, no userinfo/query/fragment, hostname `localhost` or `ipaddress.ip_address(host).is_loopback`; else `ValueError` naming the variable. Positive timeout, valid provider; native requires `OPENCODE_MODEL`, both native vars, and a Slice 3-recorded auth header for that provider.
- D19 OpenCode does not depend on `ModelClient` (Out-1); discovery stays orchestrator-side (Out-2).
- D20 (C-1) Read-only `RunLifecycleService.is_run_live(session, run_pk) -> Literal["active","closing","lost"]` on `id == run_pk`, `finished_at IS NULL`. `heartbeat_run` (408) and `_ACTIVE_RUN_STATUSES` (32) unchanged, so a closing worker stays heartbeated until D14 completes.
  - Bridge and relay check before each call: `closing` → deny "run stopping", D14 via the `manage_run` cancel path, close per §12; `lost` → deny, mark `ownership_lost`, D14, `RUN_LIFECYCLE_FAILED`. Residual: a call already running at reclaim completes, as on internal.
- D21 (C-2) Tenant isolation: each session gets its own MCP config (A3) and provider config (A14), each carrying its own per-run bearer; no sidecar-wide credential to bridge, relay or provider exists; A3 or A14 failure stops Slices 5–6.
- D22 (C-2, In-4) `engines/opencode/tool_map.py` `resolve_engine_tools(requested, user_token) -> ResolvedTools{mapped, mcp_tools, rejected}`, last D10 gate; listing via `fetch_mcp_tools(user_access_token=…)` (388) under `asyncio.timeout_at(D24)`; expiry → 504 / `TIMEOUT` before any claim. Conflict filter (hub 400–413) only when local tools are included.
  - Mapping accepts OpenCode's name charset/length and object-root `inputSchema` with allowlisted keywords (A12). Requested missing/unmapped → 400 `ENGINE_TOOL_UNSUPPORTED`; `tools` omitted (AG-UI fresh, 1773) → unmapped dropped, logged `opencode_tool_unmapped`. Engine and bridge never re-fetch; internal keeps `_select_tools` (1620).
- D23 (In-5) `engines/opencode/model_route.py` `resolve_model_route(provider, opencode_model, caller_model)`: `litellm` → relay upstream `LITELLM_BASE_URL` + `LITELLM_API_KEY`, model `OPENCODE_MODEL` else caller model (A9a); `native` → relay upstream `OPENCODE_NATIVE_BASE_URL` + `OPENCODE_NATIVE_API_KEY`, `OPENCODE_MODEL` provider-qualified (A9b). The sidecar never holds a provider credential.
- D24 (C-1, C-4) `engines/deadline.py` `SegmentDeadline(at=loop.time() + RUN_SEGMENT_DEADLINE_SEC)` created on OpenCode fresh paths before the first gate (orchestrator `execute` 697; AG-UI before 1569). `manage_run(..., deadline_sec=None)`: when set, the watchdog sleeps it instead of `segment_deadline_sec`; controllers pass `deadline.remaining()`; `<= 0` pre-claim → `TIMEOUT`, no rows. Relay streams are cut at `deadline.at`. Internal never passes it.
- D25 (C-1, C-3) `engines/opencode/client.py` `OPENCODE_PINNED_VERSION` (code constant) and `check_version()` on the A1 health endpoint, exact equality, bounded as D15. Order: `check_version` → sweep (D15) → mint scope/token → session create → prompt. Mismatch/missing/unparseable → `UNAVAILABLE` naming pinned and observed only; timeout → `TIMEOUT`; nothing to abort; log `opencode_version_mismatch`.
- D26 (C-2) `hooks/executor.py`: ContextVar `_HOOKS_SUPPRESSED` (default `False`) and `bind_hooks_suppressed()`; `run_hooks` (187) returns allow when set, before loading. Only the bridge binds it, so internal is unchanged. With D12's exclusions no bridged call starts a process (`execute_local` 519, `run_git` via `workspace_manager.py` 185, hooks 104).
- D27 (C-1, C-2, P015) `engines/opencode/relay.py`: model relay route mounted beside the bridge only when engine=opencode. Accepts only a live scope's bearer (else 401) and D20 state `active`; strips inbound auth headers, injects the D23 upstream credential, forwards method, path suffix, body and streamed response byte-for-byte (no body change, C-4); records upstream status for D16; per-run stream registry used by D14 step 3.
