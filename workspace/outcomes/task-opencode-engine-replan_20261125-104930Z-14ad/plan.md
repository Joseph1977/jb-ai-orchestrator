## Plan

### What / where / why
Insert an `ExecutionEngine` seam at the six controller calls to `ToolExecutionHub.process_request`; lifecycle (claim, heartbeat, deadline, close, persistence) stays in controllers. Engine identity is persisted per execution, per run and per await state. A headless `OpenCodeExecutionEngine` routes every tool call back through an orchestrator-hosted, per-run, ownership-fenced tool bridge. Covers In-1..In-6; Out-1..Out-4 untouched. Baseline: earlier run's plan v4, re-verified against current code.

### Segment today (Q1)
- Six call sites: `orchestrator_controller.py` execute (770) and resume (992); `ag_ui_controller.py` `_run_resume_segment` (1391) and `_run_fresh_segment` (1768); `agent_controller.py` `executeRequest` (175) and `resumeRun` (274). `tool_hub.py` 1564 is the hub's nested `task_local` call and stays internal.
- Orchestrator and AG-UI segments are one hub task inside `session_close_service.manage_run` (153), via `_managed_hub_process` (461) or `_stream_run` (807). `manage_run` owns heartbeat, the deadline watchdog (`segment_deadline_sec`, 186), cancel event + `task.cancel()`, and awaiting the worker before release; the claim is `run_lifecycle.try_create_active_run` (334).
- Legacy paths have no `ExecutionRun` claim, no `manage_run`; `executeRequest` creates a RUNNING `Execution` (`_create_execution_record`, 100) and persists only that row on completion or failure (210–216). Unchanged under internal.
- Persisted segment fields: `executions` (`status, result, error_message, config, origin`); `execution_runs` (`execution_id, thread_key, run_id, origin, channel, status, heartbeat_at, started_at, finished_at`); await snapshot `llm_states` (`execution_id, thread_id, thread_key, run_id, tool_call_id, status, state_payload`), written by `create_state` (`execution_state_service.py` 106) from orchestrator 328, AG-UI 599, agent 132.
- Result is the hub dict (`success, response, error, error_code`, counters, tokens, `tool_calls_info, agui_tool_calls, text_streamed, awaits_response, pending_tools, pending_tool, interrupts, state`); `state` from `_build_await_result` (857). Resume uses `resume_tool_results`, `resolve_resume_model`, `resolve_resume_max_tool_calls`; `prepare_hook_permission_resume_events` stays internal-only.
- The hub binds the MCP user token and request catalog as ContextVars for its own task (`tool_hub.py` 237–241, reset 853–855); `fetch_mcp_tools` binds and resets the token around listing (`mcp_agent_service.py` 395–414).

### Design decisions
- D1 (In-1) `engines/contract.py`: v1 `SegmentRequest` (all current `process_request` kwargs incl. `cancel_check`, + `event_sink`, + optional `resolved_tools`), `EngineEvent` (text/tool/usage), `SegmentResult` (TypedDict of hub keys), `AwaitEnvelope{engine, contractVersion, payload}`, `ENGINE_CONTRACT_VERSION = 1`.
- D2 (In-1) `engines/base.py` protocol: `name`, `contract_version`, `capabilities()`, `async run_segment`. Failures return `success: False`; `CancelledError` re-raised only after engine-owned work stopped (D14).
- D3 (In-2) `engines/internal.py` forwards kwargs unchanged with `event_sink=None`; rejects non-`None` `resolved_tools`. `task_local` stays inside the hub.
- D4 (In-2) `engines/resolver.py`: `resolve_fresh_engine()` reads `ORCHESTRATOR_ENGINE`; `resolve_persisted_engine(name, version)` never reads the environment. Used at all six call sites.
- D5 (Q2, C-5) Typed columns `engine VARCHAR(32) NOT NULL DEFAULT 'internal'`, `engine_contract_version INTEGER NOT NULL DEFAULT 1` on `executions`, `execution_runs`, `llm_states`; `state_payload` unchanged (C-6). `create_execution` (43), `try_create_active_run`, `create_state` gain keyword params defaulting to internal/1; `update_execution` (64) gains optional engine params.
  - Stamping: legacy `_create_execution_record` and AG-UI `_create_agui_execution` (569) pass the resolved fresh engine; orchestrator initiate (575) stamps it and each orchestrator execute/resume segment start updates it in the claim transaction (engine of the latest segment). Audit only; D7 never reads `executions.engine`.
- D6 (Q2) Alembic `20261124_engine_identity`, down-revision `20250816_phase3_lifecycle` (current head). Server default backfills existing rows of all three tables as internal/1 with the phase-3 adopt-if-present pattern; downgrade drops the columns; `executions.config` not rewritten.
- D7 (Q2, C-5) Mismatch check after state load, before any claim: orchestrator resume after `get_state` (890) before `try_claim_state_for_resume` (935); AG-UI `_handle_tool_response` after `get_resume_hold_by_tool_call_id` (1180) before claim (1257); legacy `resumeRun` after state load (251) before the hub call.
  - REST: 409 `{"success":false,"errorCode":"ENGINE_MISMATCH","error":"Run state was created by engine '<e>' contract v<n>; this deployment cannot resume it"}` (shape of `_run_conflict_payload`). AG-UI: `RunErrorEvent("ENGINE_MISMATCH: …")`.
  - State stays `AWAITING_RESPONSE`, no `ExecutionRun`; legacy returns before its `DISCARDED` branch (286). Internal state resumes on internal under either setting.
- D8 (Q3) OpenCode v1 has no resume mode: never awaits, writes no `llm_states`, `durable_resume=false`. First mode later (Out-3) is the translated snapshot: a session reference pins resume to one process's sidecar (D11), breaking replica independence (`docs/ORCHESTRATOR.md` §10). Rejection tested with a crafted `engine='opencode'` row.
- D9 (Q4, In-4) `engines/capabilities.py`: `headless_segment, workspace_file_ops, mcp_tools, streaming_output, agui_frontend_interrupts, durable_resume, hooks, permission_asks, subagents, context_compaction, multimodal_reads, workspace_free`. Internal: all true. OpenCode: `headless_segment`, `workspace_file_ops`, `streaming_output` true; `mcp_tools=subset` (D22); rest false.
- D10 (Q4, In-4) `require_capabilities(engine, needs)` → 400 / `RunErrorEvent` `ENGINE_CAPABILITY_UNSUPPORTED` naming the capability; denial logged with engine, version, capability. Internal never gated. Gate points:
  - Orchestrator `execute`: after `_segment_config` (707), before the claim session (710); `Execution` status untouched.
  - AG-UI fresh: frontend-tool gate before binding resolution (1569); binding-dependent gates after `except BindingError` (1597), before `sanitize_execution_config` (1601) and `_create_agui_execution` (1621, inserts a RUNNING `Execution`, 569).
  - Legacy `executeRequest`: before `_create_execution_record()` (158), so rejection leaves no `Execution` row.
  - Earlier `ensure_thread_session` (1449), `_prepare_thread_claims` (1474) and input-branch `ensure_runtime` (1582) run before gates as for binding errors; no `Execution`/`ExecutionRun`; thread stays runnable.
  - Gates: non-empty `frontendTools`; `hooks` when `Config.HOOKS_ENABLED` (`config.py` 289); `subagents` when `Config.SUBAGENT_ENABLED` (278); `context_compaction` when `Config.CONTEXT_COMPACTION_ENABLED` (272); `multimodal_reads` when `Config.MULTIMODAL_ENABLED` and the run exposes local tools; `workspace_free` when AG-UI `input_binding is None` and always on legacy `executeRequest`; then D22 tool resolution, last.
  - `hooks` is flag-only: hook config is re-read at every event (`hooks/executor.py` 199), and with the flag off `run_hooks` returns allow (196), incl. `execute_local`'s `afterShellExecution` (`local_tool_provider.py` 555).
  - The four flags are process-global, so an OpenCode deployment sets them `false`; the error names capability and flag. No new setting or default (C-4); internal unaffected (C-6).
  - No await can arise: `ask_user_local` is never offered (D12), so no pre-claim gate is needed for it.
  - In-segment re-check fails as an attempt (§12): `local_context is None` (ignored `workspacePath` when `ALLOW_INPLACE_WORKSPACE=false`, 387).
- D11 (C-2) One loopback sidecar per orchestrator process, operator-launched (not spawned by the orchestrator), sharing its network namespace; no workspace mount; each session rooted in an empty per-run scratch dir; orchestrator-composed system prompt sent as session system prompt (A4).
- D12 (C-2) `engines/opencode/bridge.py`: internal MCP route mounted in `main.py` (99–102) only when engine=opencode.
  - Local listing and dispatch only when `local_tool_provider.enabled`; otherwise none listed and a forged local call returns "not available", executing nothing. Listing `list_litellm_tools(exclude_base={"task","ask_user"}, mode, output_bound)` + `resolved_tools.mapped`, no AG-UI tools; dispatch refuses any name outside that list, so a forged `ask_user_local`/`task_local` call returns "not available".
  - MCP dispatch per call, in the bridge handler task: check name ∈ `scope.resolved.mapped`; `t1 = bind_mcp_user_token(scope.user_token)`, `t2 = bind_request_mcp_tools(scope.resolved.mcp_tools)`; `await mcp_service.execute_mcp_tool(original_name, args)`; `finally` reset `t2`, then `t1`. Never relies on ContextVars inherited from the controller or preflight.
  - Media markers (`multimodal: true`, `local_tool_provider.py` 192, `multimodal.py` 86): `absolutePath` always stripped; otherwise returned as internal returns it with `MULTIMODAL_ENABLED=false` (`multimodal.py` 191).
  - Per-run 256-bit in-memory bearer bound to `(run_pk, LocalToolContext, registry, budget, user MCP token, ResolvedTools)`; bad token → 401.
  - Local calls via `LocalToolProvider.execute` (1083): tool policy, `resolve_within`, path policy, workspace opener. User MCP token never reaches the sidecar; OpenCode built-ins disabled per session (A2).
- D13 (C-4) `maxToolCalls`: request → segment config → `MAX_TOOL_CALLS`, counted in the bridge. `OPENCODE_REQUEST_TIMEOUT_SEC` is a per-sidecar-request infrastructure guard; the segment deadline (D24) caps the run. `OPENCODE_MODEL`/`OPENCODE_PROVIDER` inert unless engine=opencode.
- D14 (C-1) Shielded stop sequence on cancel, `CancelledError`, completion, failure or lost ownership; swallows repeated `task.cancel()`:
  1. Close bridge admission; late calls get "run stopping" and execute nothing.  2. Send abort to the sidecar.
  3. Await every in-flight call in the run's `BridgeRunScope`. MCP calls cancelled then awaited; local tools run to their own bound, since cancelling `execute_local` at `proc.communicate()` orphans the subprocess (`local_tool_provider.py` 519–530).
  4. Poll the sidecar until idle (A6).  5. Revoke the token, then return or re-raise.
  - The worker lives until step 5, so heartbeat stays fresh and `worker_cancellation_slow` fires; nothing released on elapsed time. Only loopback connection-refused counts as "sidecar stopped" (A7); D18 guarantees the URL is loopback.
- D15 (C-1) Crash orphans: stale-claim recovery (`mark_stale_runs_failed` in `try_create_active_run`, 368) unchanged; token and scope die with the process; startup `sweep.py` aborts and deletes tagged sidecar sessions on the process's own loopback sidecar (A1).
- D16 (Q5, C-3) Every in-segment failure runs D14 then returns `success: False`; controllers apply the §12 table unchanged; raw sidecar bodies never returned. Codes: `UNAVAILABLE` (down, health/version fail); `TIMEOUT` (request timeout, segment deadline); `ENGINE_PROTOCOL_ERROR` (malformed event, partial stream); `QUOTA`/`RATE_LIMIT`/`AUTH`/`UNAVAILABLE` for provider errors (A10); `RUN_LIFECYCLE_FAILED` on lost ownership (D20). `ENGINE_TOOL_UNSUPPORTED` only pre-claim (D22).
- D17 (In-3) Sidecar stream supplies text, usage, completion; the bridge supplies authoritative `TOOL_CALL_*` events, `tool_calls_info` and counters. `event_sink` publishes via `agui_event_service` and sets `text_streamed`.
- D18 (In-5) `config.py`: `ORCHESTRATOR_ENGINE` (default `internal`), `OPENCODE_BASE_URL`, `OPENCODE_REQUEST_TIMEOUT_SEC=300`, `OPENCODE_MODEL`, `OPENCODE_PROVIDER=litellm|native`, infra `OPENCODE_TOOL_BRIDGE_URL` (default `http://127.0.0.1:8000`). `validate_config` (384) checks the engine value; only when opencode:
  - `_require_loopback_url(name, value)` for both URLs: scheme `http`, no userinfo/query/fragment, `urlparse().hostname` equal to `localhost` or `ipaddress.ip_address(host).is_loopback`; else `ValueError` naming the variable. Rejected: other hostnames (`localhost.example.com`, `host.docker.internal`), `0.0.0.0`, `::`, IPv4-mapped IPv6, private/public IPs.
  - Positive timeout, valid provider, non-empty `OPENCODE_MODEL` for native. Any of `HOOKS_ENABLED`, `SUBAGENT_ENABLED`, `CONTEXT_COMPACTION_ENABLED`, `MULTIMODAL_ENABLED` true logs `opencode_capability_flag_enabled` naming it (boot continues; D10 rejects runs).
- D19 OpenCode does not depend on `ModelClient` (Out-1); no discovery adapter needed (Out-2): discovery stays orchestrator-side.
- D20 (C-1) New `RunLifecycleService.is_run_live(session, run_pk)`: the `heartbeat_run` predicate (408) narrowed from `_ACTIVE_RUN_STATUSES` (32) to `status == active`. Bridge checks before each call; not live → deny, mark scope `ownership_lost`, D14, `RUN_LIFECYCLE_FAILED`. Residual: a call already running at reclaim completes, as on internal (§12).
- D21 (C-2) Tenant isolation: each session gets its own MCP config with its own per-run bearer (A3); no shared sidecar-wide credential exists. There is no fallback: A3 failure stops Slices 5–6.
- D22 (C-2, In-4) `engines/opencode/tool_map.py` `resolve_engine_tools(requested, user_token) -> ResolvedTools{mapped, mcp_tools, rejected{name: reason}}`, last D10 gate on OpenCode fresh paths; `mcp_tools` keeps the `MCPTool` objects D12 binds.
  - Listing via `mcp_service.fetch_mcp_tools(user_access_token=…)` (388), `MCP_FETCH_TIMEOUT_SEC` unchanged, whole call under `asyncio.timeout_at(D24 deadline)`; expiry → 504 / `RunErrorEvent` `TIMEOUT` before any claim. `FILTER_MCP_TOOLS_CONFLICTING_WITH_LOCAL` applied only when local tools are included (hub 400–413).
  - Mapping accepts names in OpenCode's charset/length and object-root `inputSchema` with allowlisted keywords (A12). Requested missing/unmapped → 400 / `ENGINE_TOOL_UNSUPPORTED` naming tool and reason. `tools` omitted (always on AG-UI fresh, 1773) → unmapped dropped, logged `opencode_tool_unmapped`.
  - `ResolvedTools` travels in `SegmentRequest.resolved_tools`; engine and bridge never re-fetch. Internal keeps in-segment `_select_tools` (1620) unchanged (C-6).
- D23 (In-5) `engines/opencode/model_route.py` `resolve_model_route(provider, opencode_model, caller_model)`: `litellm` uses the sidecar's LiteLLM provider with `OPENCODE_MODEL` else caller model (A9a); `native` uses `OPENCODE_MODEL` provider-qualified (A9b). Native credentials only in the sidecar env, never in orchestrator env (copied by `execute_local`, 515).
- D24 (C-1, C-4) `engines/deadline.py` `SegmentDeadline(at=loop.time() + RUN_SEGMENT_DEADLINE_SEC)`, `remaining()`. Created on OpenCode fresh paths before the first gate: orchestrator `execute` entry (697); AG-UI fresh before 1569 (§12: deadline covers preparation).
  - `manage_run(..., deadline_sec: float | None = None)`: when set, the watchdog sleeps that instead of `segment_deadline_sec` (186); `_managed_hub_process`/`_stream_run` pass it through; their existing test callers omit it.
  - Controller passes `deadline.remaining()` right before `manage_run`. `<= 0` before claim → `TIMEOUT`, no rows; after claim → `TIMEOUT` attempt (§12). Internal never passes `deadline_sec` (C-6); no new setting (C-4).
